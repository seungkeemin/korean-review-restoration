# korean-review-restoration

자모 단위로 난독화된 한글 리뷰를 원문으로 복원합니다. 학습 데이터에서 자모 치환 빈도를 세고, 단어마다 빔 서치로 후보를 만든 뒤, 단어 간 연결 확률로 Viterbi 탐색을 해 문장을 고릅니다.

## 과제 개요

Dacon "난독화된 한글 리뷰 복원 및 생성 AI 경진대회" 데이터로 진행한 WeTIE 16기 머신러닝 세션 팀 프로젝트(4명, 2025년 3월 ~ 12월)입니다. 입력은 초성·중성·종성이 확률적으로 바뀐 리뷰이고(예: `방이 넓고 깨끗해요`가 `빵위 넒꼬 깨끗햬욘`처럼 바뀜, 직접 만든 예시), 출력은 원문입니다. 띄어쓰기는 보존됩니다. 학습 데이터 11,263개, 테스트 1,689개입니다.

대회 규정상 데이터는 저장소에 넣지 않습니다. 코드와 실험 노트북만 있습니다.

## 접근 방식

세 가지 방법을 차례로 시도했습니다.

| 시도 | 방법 | 팀 발표 자료의 점수 | 한계 |
|---|---|---:|---|
| 1 | 랜덤 포레스트: 앞뒤 2개 자모를 보고 가운데 자모를 분류 | 0.8653 | 자모끼리만 보고 글자나 단어를 고려하지 않음 |
| 2 | KNN: 학습 데이터 원문의 단어를 TF-IDF로 벡터화하고 가장 가까운 단어로 대체 | 0.8776 | 학습에 없던 단어는 전혀 복원하지 못함 |
| 3 | 자모 치환 통계 + 빔 서치 + 단어 Viterbi | 0.9454 | 한 단어가 틀리면 뒤 단어 선택까지 영향을 받음 |

점수는 팀 발표 자료에 적힌 대회 제출 점수이고, 리더보드 기록과는 아직 대조하지 않았습니다. 대회 평가 지표가 아래 hold-out 정확도(단어·문장 완전 일치)와 다르므로 두 숫자를 직접 비교할 수는 없습니다.

최종 방법(시도 3)은 이렇습니다.

1. **자모 치환 빈도.** 학습 쌍마다 난독화 입력과 원문을 음절 단위로 레벤슈타인 정렬하고, 음절(초성·중성·종성 묶음)이 어떤 음절로 바뀌었는지 셉니다. 단어 안에서 인접한 두 음절이 함께 바뀐 경우(bigram)도 따로 셉니다.
2. **단어 후보(빔 서치).** 난독화된 단어의 음절을 앞에서부터 바꿔 가며 점수 log(1 + bigram 빈도) + λ·log(1 + 단일 치환 빈도)가 높은 경로 160개를 유지합니다. 끝에서 log(1 + 단어 빈도)를 더해 실제로 있는 단어를 우선하고 상위 15개를 후보로 남깁니다.
3. **문장(Viterbi).** 단어마다 후보 15개가 있는 격자에서 후보 점수 + 2.5 × log P(단어 | 앞 단어)의 합이 가장 큰 경로를 고릅니다. 단어 bigram 확률은 학습 원문에서 add-1 smoothing으로 셉니다.
4. **뒤에서부터.** 한국어는 조사와 어미가 뒤에 붙으므로 문자열을 뒤집어 학습하고 복원한 뒤 다시 뒤집습니다.

## 구현

```
korean-review-restoration/
├── src/restore/
│   ├── jamo.py       음절 ↔ 초성·중성·종성
│   ├── align.py      레벤슈타인 정렬
│   ├── maps.py       단일·bigram 치환 빈도, 단어 빈도, 단어 bigram 로그확률
│   ├── decode.py     단어 빔 서치, 문장 Viterbi, 뒤집기 모드
│   └── evaluate.py   단어·문장 정확도
├── scripts/holdout_eval.py   학습 데이터 일부를 떼어 두고 out-of-sample 정확도 측정
├── experiments/              팀 실험 노트북 원본 21개 (출력 삭제)
│   ├── 랜덤 포레스트/, knn.ipynb, gpu 모델/          시도 1·2와 XGBoost·LightGBM 변형
│   ├── 통계적 모델/, 통계 + 랜덤 포레스트/            통계 방법 변형
│   ├── LLM_없이 0.9363.ipynb                        빔 서치만 쓴 버전
│   └── viberti.ipynb                                최종 버전 (src/restore와 같은 알고리즘)
├── docs/코드 분석.hwpx
└── tests/
```

- `src/restore`는 `viberti.ipynb`의 함수를 모듈로 옮긴 것입니다. 학습 데이터에서 무작위로 고른 300개로 학습하고 다른 40개를 복원했을 때 원래 노트북과 출력이 40개 모두 같았습니다.
- 실험 노트북은 출력을 모두 지웠습니다. 출력에 대회 데이터가 찍혀 있기 때문입니다. 데이터를 받던 Google Drive 파일 ID도 `YOUR_DRIVE_FILE_ID`로 바꿨습니다.

## 실행 결과

`python scripts/holdout_eval.py train.csv` 출력입니다. 학습 데이터 11,263개 중 10%(1,126개)를 떼어 두고 나머지로 통계를 만든 뒤 떼어 둔 리뷰를 복원했습니다. 하이퍼파라미터는 최종 제출과 같습니다(λ = 0.1, 빔 160, 후보 15, 문맥 가중치 2.5).

| 설정 | 단어 정확도 | 문장 정확도 |
|---|---:|---:|
| 복원하지 않음 (입력 그대로) | 3.72% | 0.18% |
| 최종 (뒤집기), seed 0 | 86.65% | 24.69% |
| 정방향, seed 0 | 85.76% | 25.49% |
| 최종 (뒤집기), seed 1 | 86.11% | 24.69% |
| 정방향, seed 1 | 85.26% | 23.62% |

| seed 0, 최종 | 값 |
|---|---:|
| 떼어 둔 단어 중 학습 원문에 없는 단어 비율 | 14.49% |
| 학습 원문에 있던 단어의 정확도 | 93.84% |
| 학습 원문에 없던 단어의 정확도 | 44.20% |

## 결과 분석

단어 정확도는 86.7%이지만 학습 원문에 있던 단어만 보면 93.8%, 없던 단어는 44.2%입니다. 떼어 둔 리뷰 단어의 14.5%가 학습 원문에 없는 단어이고, 틀린 단어의 약 60%가 여기서 나옵니다. 빔 서치 점수가 단어 빈도를 더해 "이미 본 단어"를 우선하도록 설계되어 있어서, 처음 보는 단어는 치환 빈도만으로 복원해야 합니다.

뒤집기 모드는 두 분할 모두에서 단어 정확도를 약 0.9%p 올렸습니다. 문장 정확도는 분할에 따라 오르기도 내리기도 해서 차이를 말하기 어렵습니다.

문장 정확도가 25% 안팎인 것은 리뷰 하나에 단어가 여러 개라 하나만 틀려도 문장 전체가 틀리기 때문입니다.

**한계.** 단어 하나의 후보가 틀리면 Viterbi가 그 단어와 잘 이어지는 다음 단어를 고르면서 오류가 번질 수 있습니다. 처음 보는 단어에 약한 것은 사전 기반 설계의 한계이고, 형태소 단위 분석이나 학습 데이터 증식, 딥러닝 모델이 다음 단계 후보입니다.

## 이슈 기록

**학습 데이터로 잰 정확도가 과대평가됨.** 실험 중 통계 방법의 한 변형(`experiments/통계적 모델/statistics1.ipynb`)은 통계를 만든 학습 데이터 일부를 복원해 단어 정확도 94.97%를 기록했습니다. 같은 데이터로 통계를 만들고 평가했기 때문에 처음 보는 단어가 없는 조건입니다. 포트폴리오로 정리하면서 hold-out 평가를 따로 만들어 86.7%를 다시 쟀습니다. 랜덤 포레스트의 Train Accuracy 0.9534(`rf1.ipynb`)도 같은 이유로 일반화 성능이 아닙니다.

**노트북 출력과 데이터 경로.** 실험 노트북 출력에 테스트 데이터 행이 그대로 찍혀 있었고, 몇몇 노트북은 공유 Drive에서 데이터를 받도록 파일 ID가 코드에 들어 있었습니다. 공개 전에 출력과 ID를 모두 지웠습니다.

## 실행 방법

Python 3.10 이상. 외부 패키지 없이 표준 라이브러리만 씁니다.

```bash
pip install -e ".[dev]"
pytest
```

대회 데이터(`train.csv`)가 있으면:

```bash
python scripts/holdout_eval.py path/to/train.csv
```

```python
from restore import fit, restore
model = fit(list(zip(train_inputs, train_outputs)))
restore("빵위 넒꼬 깨끗햬욘", model)
```

## 개발 방식

실험 노트북은 팀이 세션 기간에 작성했습니다. 포트폴리오 정리에는 Claude Code를 써서 최종 노트북을 `src/restore` 모듈로 옮기고, hold-out 평가 스크립트, 테스트, CI, 이 README를 추가했습니다.

검증은 이렇게 했습니다.

- 모듈로 옮긴 뒤 원래 노트북 함수와 같은 입력으로 돌려 출력이 모두 같은지 확인했습니다.
- 테스트는 대회 데이터 없이 직접 만든 문장과 결정적인 난독화 규칙으로 돕니다. 파이프라인이 학습한 규칙을 되돌리는지(단어·문장 정확도 100%), Viterbi가 문맥으로 동점을 가르는지 확인합니다.
- README 수치는 모두 `scripts/holdout_eval.py`를 직접 돌린 출력입니다. 대회 점수(0.8653, 0.8776, 0.9454)만 팀 발표 자료에서 옮겼습니다.
